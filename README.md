# Aslema @ NADI-2026 Shared Task 5 — Spoken Language Understanding for Tunisian Derja

Code for our system paper: zero-shot and LoRA-fine-tuned audio LLMs for
**intent recognition** (Subtask 5.1) and **slot filling** (Subtask 5.2) on
[SLURP-TN](https://huggingface.co/datasets/elyadata/SLURP-TN), plus the
**LLM + TTS synthetic augmentation pipeline** that produced our submitted system.

Submitted system: **Qwen3-Omni-30B-A3B**, one LoRA adapter trained jointly on both
subtasks for two epochs over *real train + synthetic* data.
Official blind test: **1st in slot filling**, **4th of 8 in intent recognition**.

## Layout

Python lives under `bin/`, shell and Slurm job scripts under `scripts/`, mirroring
each other stage for stage.

```
config.sh                     ONE entry point: paths, models, conda, Slurm  — source this first
requirements.txt              deps for the main environment
prompts.txt                   every prompt, GENERATED by bin/tools/build_prompts_txt.py
conf/
  labels/                     intent (23) and slot (34) inventories
  voxcpm_slurptn_lora.yaml     VoxCPM LoRA fine-tuning config
docs/
  pipeline.png                augmentation pipeline figure
  AUGMENTATION.md             the pipeline, stage by stage

bin/                          python
  prompts/                    prompt builders (imported by the jsonl converters)
  data_prep/                  manifests -> ms-swift jsonls, label extraction,
                              60-label open-inventory + official-test variants
  augmentation/               seed_pool -> generate -> validate -> judge -> build_manifests
    tts/                      reference scoring/selection, VoxCPM synthesis
  train/  inference/  eval/   whisper baseline, whisper inference, official scorers
  tools/                      build_prompts_txt.py

scripts/                      shell / sbatch
  setup/setup_env.sh          build the main conda environment
  common.sh                   shared job runtime (caches, conda, modules)
  data_prep/                  prepare_slurptn.sh
  augmentation/               run_pipeline.sh, tts/ (setup, synthesis, VoxCPM fine-tune)
  training/  inference/  eval/  LoRA SFT, merge, batch inference, scoring
```

## Environments

Two environments are required, because VoxCPM pulls a torch build that conflicts
with the ms-swift/vLLM pins. Every script says which one it needs.

| # | what | used for | built by |
|---|---|---|---|
| 1 | conda env `$ENV_NAME` (default `aslema`), python 3.11 | data prep, training, inference, evaluation, and the LLM stages of augmentation | `scripts/setup/setup_env.sh` |
| 2 | venv under `data/tts_venv` | VoxCPM speech synthesis only | `scripts/augmentation/tts/setup_voxcpm.sh` |

```bash
git clone https://github.com/hunzed/aslema_nadi2026 && cd aslema_nadi2026
$EDITOR config.sh                         # set CONDA_SH, ENV_NAME, Slurm account/QOS
source config.sh
bash scripts/setup/setup_env.sh           # environment 1
bash scripts/augmentation/tts/setup_voxcpm.sh   # environment 2 (only if you synthesize speech)
export GOOGLE_API_KEY=...                 # only for the augmentation LLM stages
```

## Reproducing the paper

**1. Data preparation** — downloads SLURP-TN, writes manifests, label inventories
and the per-family ms-swift jsonls (inference + SFT targets):

```bash
sbatch scripts/data_prep/prepare_slurptn.sh
```

**2. Zero-shot inference** (Table 2) — any of the four backbones:

```bash
sbatch --export=ALL,MODEL=Qwen/Qwen3-Omni-30B-A3B-Instruct,MODEL_NAME=qwen3_omni_30b_a3b,\
FAMILY=qwen,SUBTASK=intent,SPLIT=test scripts/inference/infer_finetuned.sh
```

**3. LoRA fine-tuning** (one adapter, both subtasks, two epochs) then merge and
re-infer:

```bash
sbatch --export=ALL,MODEL=Qwen/Qwen3-Omni-30B-A3B-Instruct,MODEL_NAME=qwen3_omni_30b_a3b,\
FAMILY=qwen,SUBTASK=joint,NUM_EPOCHS=2 scripts/training/sft_lora.sh
sbatch --export=ALL,CKPT=<checkpoint dir> scripts/training/merge_lora.sh      # 30B: manual_merge_lora.sh
sbatch --export=ALL,MODEL=<merged dir>,MODEL_NAME=<slug>_sft,FAMILY=qwen,SUBTASK=intent,\
SPLIT=test scripts/inference/infer_finetuned.sh
```

Recipe (identical for every model): LoRA rank 16, alpha 32 on the language
backbone's `q,k,v,o_proj`; audio encoder and audio–text aligner frozen;
lr 1e-4; effective batch 8; max length 4096; bf16; 2 epochs; final checkpoint served.

**4. Whisper-small baseline** — full fine-tune, 2 epochs, `[INTENT]`/`[SLOT]`
marker forced at decoding:

```bash
python bin/train/train_whisper.py --joint --epochs 2 --lr 1e-5 --batch 16
python bin/inference/infer_whisper.py --model-dir <dir> --subtask intent --split test --joint
```

**5. Scoring** — the organizers' metrics:

```bash
sbatch scripts/eval/eval_all_intent.sh      # accuracy, macro-F1, weighted-F1
sbatch scripts/eval/eval_all_slot.sh        # WER, CER, CoER, CVER
```

**6. Official test set + abstention.** The blind test is scored over the full
60-label SLURP inventory, which the released 23-label prompt cannot express.
`bin/data_prep/make_open_inventory_infer.py` rewrites the test jsonl with the
60-label + `unknown` prompt (Part 2 of `prompts.txt`); the abstention rule that
folds the catch-all `general_quirky` into `unknown` is
`bin/eval/make_intent_submission_quirky2unk.py`.

### Prompts

Every prompt the system sends is collected in [`prompts.txt`](prompts.txt): the two task
prompts (used identically zero-shot and as fine-tuning targets), the 60-label
open-inventory prompt for the official test set, and the augmentation generation,
judging and reference-ASR prompts. It is **generated** from the modules that send them:

```bash
python bin/tools/build_prompts_txt.py           # regenerate
python bin/tools/build_prompts_txt.py --check   # fail if out of date (CI-friendly)
```

## Synthetic data augmentation

See [`docs/AUGMENTATION.md`](docs/AUGMENTATION.md) — full detail in
[`docs/AUGMENTATION.md`](docs/AUGMENTATION.md). Summary of what runs:

| stage | tool | output |
|---|---|---|
| quotas from label frequency (more data for rarer intents) | `bin/augmentation/seed_pool.py` | per-intent quotas + few-shot seeds (**train split only**) |
| few-shot generation, 3 modes (coverage / paraphrase / distractor) | `bin/augmentation/generate.py` | 20,937 raw candidates |
| deterministic validation (grammar, label inventory, script ratio, length, near-dup) | `bin/augmentation/validate.py` | 13,876 |
| 3-model judging panel, keep on 2-of-3 majority | `bin/augmentation/judge.py` | **12,138 utterances** |
| voice-cloned TTS, base **and** SLURP-TN-LoRA VoxCPM2, shared 152-clip reference pool | `bin/augmentation/tts/` | 23,300 renditions |
| deterministic acoustic screen (duration, level, clipping, activity, speaking rate) | `bin/augmentation/build_manifests.py` | **22,940** (+2,677 real = 25,617 mixed) |

The acoustic screen is the **only** filter applied to the synthetic audio; no
per-clip LLM authenticity check was run (a 650-clip listening study was used only
to pick the base TTS variant for the mixed set).
